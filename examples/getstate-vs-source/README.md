# getState() vs source: Примеры проблем и правильного использования

Этот набор примеров демонстрирует реальные проблемы, которые возникают при использовании `getState()` вместо передачи стора через параметр `source` в Effector.

## Обзор проблем

### 1. Race Condition (01-race-condition.ts)

**Проблема:** При асинхронных операциях значение стора может измениться между вызовом `getState()` и использованием значения.

**Пример:** Загрузка данных пользователя - если пользователь быстро переключается между аккаунтами, данные могут загрузиться для неправильного пользователя.

### 2. Fork/Scope Issues (02-fork-scope-issue.ts)

**Проблема:** `getState()` всегда обращается к глобальному состоянию, игнорируя изолированные scope. Критично для SSR.

**Пример:** На сервере при обработке нескольких запросов одновременно, данные одного пользователя могут "утечь" другому.

### 3. Потеря реактивности (03-reactivity-loss.ts)

**Проблема:** `getState()` не создает реактивную зависимость. Изменения стора не отслеживаются.

**Пример:** Применение настроек пользователя - могут применяться устаревшие значения.

### 4. Валидация формы (04-form-validation.ts)

**Проблема:** При быстром вводе или автозаполнении разные поля формы могут быть получены в разное время, что приводит к несогласованности.

**Пример:** Валидация формы регистрации - пароль и подтверждение могут не совпадать из-за рассинхронизации.

## Общие рекомендации

### ❌ Когда НЕ использовать getState()

1. **В эффектах внутри sample** - используйте параметры эффекта
2. **При работе с SSR/fork** - всегда используйте source
3. **При комбинировании нескольких сторов** - используйте combine + source
4. **В асинхронных операциях** - значение может устареть

### ✅ Когда МОЖНО использовать getState()

1. **Отладка и логирование** - для просмотра текущего состояния
2. **Синхронные вычисления вне графа** - когда не нужна реактивность
3. **Интеграция с внешними библиотеками** - в callback'ах вне Effector

## Правильный паттерн

```typescript
// ❌ Неправильно
sample({
  clock: someEvent,
  fn: () => {
    const value = $store.getState() // Плохо!
    return processValue(value)
  },
  target: someTarget,
})

// ✅ Правильно
sample({
  clock: someEvent,
  source: $store, // Хорошо!
  fn: (value) => processValue(value),
  target: someTarget,
})
```
